# Android 1.0.1 接收文件打开

在电脑选择或拖入文件，手机接收完成后，在 APK 的传输记录点击“打开”。
每次都会调用系统“选择打开方式”，由相册、PDF 阅读器等已安装应用查看。
zhanhBlueB 不包含通用文件查看器，不会在接收后自动弹出应用。

## 记录与文件

- 文件完成 SHA-256 校验并保存到 `下载/zhanhBlueB` 后才显示“打开”。
  记录保存 MediaStore 返回的实际 URI、重名后的文件名、类型、大小和完成时间。
- 最近 100 条成功接收文件记录保存在应用私有目录，重启 APK 或断开蓝牙后仍能打开。
  记录按传输编号合并，不重复显示；超过限制只裁剪记录，不删除下载文件。
- 此入口适用于电脑选择、多选或拖入的普通文件，包括 JPG/PNG、PDF 和文本。
  电脑复制的剪贴板图片仍沿用原有剪贴板与手动另存行为，不加入长期记录。
- 历史从升级后新接收的文件开始建立。原有下载文件保留，不自动扫描导入。
  卸载或清除应用数据会移除记录；手动移动、删除下载文件会使对应记录失效。

## 打开方式与提示

只把文件的 `content://` URI 和临时读取权限交给选中的应用，不授予写入、
长期读取或全盘存储权限。优先使用系统返回的具体 MIME 类型，然后使用接收类型、
扩展名推断，未知类型或没有匹配应用时尝试通用选择器。
没有可用应用、文件不存在或读取权限失效时显示中文提示。

选择器打开期间会禁用打开按钮，避免重复启动。取消选择器或打开失败不会改变
文件传输成功状态。历史记录采用版本化 JSON 和 AtomicFile 原子保存；
记录保存失败时当前文件仍可打开，同时提示重启后可能丢失这条记录。

## 升级与验收

安装 `zhanhBlueB-Android-1.0.1.apk` 覆盖旧版本，包名不变、versionCode 升至 2，
继续使用原签名。无需卸载或升级 Windows 1.0.2，蓝牙协议不变。

真机检查：双向正常连接后，用电脑选择或拖入 JPG/PNG、PDF、文本、未知扩展名、
中文/表情文件名、同名文件和空文件。手机接收后逐项点击“打开”，检查选择器、
查看应用读取的实际文件及重名副本。取消选择、删除一个测试文件、重启 APK、
断开蓝牙后再次打开，并验证剪贴板图片没有新增自动保存。
